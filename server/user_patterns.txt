🟦 1. Best Time to Buy and Sell Stock

🧠 Pattern: Greedy / Minimum So Far Pattern

The key idea is:

Keep track of the lowest price seen so far, and calculate the profit if you sell today.

If prices are:

[7, 1, 5, 3, 6, 4]

When the current price is 6:

profit = 6 - 1 = 5

So instead of trying every possible buy-sell pair, you ask:

“What is the cheapest price I have seen before today?”

What you learned from Best Time to Buy and Sell Stock
Track the minimum so far → cheapest buying price
Calculate profit at every position → current price - minimum price
Keep the maximum profit
Avoid checking every pair
Brute force: O(n²)
Greedy: O(n)
🔥 The reusable pattern

When you need the best result involving a previous element, think:

“What is the best previous value I need to remember?”

This pattern appears in stock problems, maximum differences, and optimization problems.

So your takeaway is:

Best Time to Buy and Sell Stock → Minimum So Far + Maximum Profit → “What is the best previous value?”

🟦 3. Maximum Subarray

🧠 Pattern: Kadane’s Algorithm / Running Best Pattern

The key idea is:

At every position, decide whether to continue the current subarray or start a new one.

Suppose the current running sum becomes negative.

Keeping that negative sum will only hurt future elements.

So you ask:

“Is it better to continue with what I have, or start fresh from here?”

What you learned from Maximum Subarray
Maintain a running sum
Discard a harmful previous sum
Track the best sum found so far
Make a local decision at every element
Avoid checking every possible subarray
Brute force: O(n²) or worse
Kadane: O(n)
🔥 The reusable pattern

When a problem asks for the best contiguous segment, think:

“Should I extend the current segment or start a new one?”

This is the foundation of Kadane's Algorithm.

So your takeaway is:

Maximum Subarray → Kadane’s Algorithm → “Continue or restart?”

🟦 4. Product of Array Except Self

For:

The important observation is:

You don't need to repeatedly calculate the entire product.

What you learned from Product of Array Except Self

Prefix = information from the left
Suffix = information from the right
Combine prefix and suffix
Avoid division because of zero-related issues
🔥 The reusable pattern

“Can I precompute information from the left and right?”

This pattern appears in prefix sums, suffix sums, products, range queries, and array optimization.

So your takeaway is:

Product of Array Except Self → Prefix + Suffix → “What information exists on my left and right?”

Climbing Stairs → DP + Fibonacci → “Current ways = previous ways + two-steps-back ways.”
